# C-2 : critique utilisateur final, angle friction zero sur mobile

Hypotheses : proprio sur mobile 360px, Safari iOS + Chrome Android, 4G moyenne. Destinataire sans compte, ouvre depuis SMS ou WhatsApp, lit en 30 secondes ou abandonne. Tout tap, chargement ou doute en trop est un echec.

## 1. Parcours simules

### A. Creer un lien depuis mobile (proprio presse)
Etapes : ouvrir admin, taper cle, chercher note, regler duree, taper Creer, copier URL, coller dans WhatsApp.
P-lecture-first : OK sur le papier. Ordre filtre puis creation puis liens validé. Risques : CTA sticky bas masque par clavier iOS si mal positionne avec `position: sticky` seul. Succes avec Copier 48px bien, mais pas de precision sur retour visuel apres copie (le proprio retape Copier 3 fois).
P-admin-power : meilleur sur ce parcours. Recherche sticky + compteur + croix, segments 24h/7j/30j, details replies, erreurs inline avec focus premier fautif. Friction : bottom sheet de revocation custom = code en plus, risque focus piege rate au clavier, et header charge (statut cle + deconnexion + theme sur 360px = surcharge).
P-robuste : meme squelette que lecture-first, en plus simple. Confirm natif au lieu de bottom sheet : 1 tap de moins a coder, mais `confirm()` natif sur iOS coupe le contexte et affiche un texte brut anxiogene. Bon point : etats vide et hors ligne avec Reessayer explicites, seul a le prevoir cote creation.

### B. Ouvrir un lien recu (destinataire sans compte)
Etapes : tap lien, premier paint, comprehension en 3 secondes, scroll, fin.
Les 3 proposent le meme hero minimal + progression 3px + article 65ch. Differences qui comptent :
P-lecture-first : bouton theme dans top bar publique = bruit pour un lecteur de passage. Temps lecture affiche : utile mais faux si calcul naif sur code + tableaux. Sommaire `details` ouvert si 3+ h2 : pousse le contenu sous la ligne de flottaison sur petit ecran.
P-admin-power : header minimal sans theme decrit ici, donc plus net. Mais `max-width: 46rem` contre 40rem ailleurs : lignes plus longues sur mobile large, confort moindre. Zebrage tableaux : ajoute du poids visuel pour un lecteur pressé.
P-robuste : seul a formuler le repli sans JS ni CDN : texte lisible meme si KaTeX ou Fonts tombent. Bouton haut de page apres 2 ecrans : pertinent sur longue note. Seul a imposer `defer` partout et aucun CSS bloquant, donc premier paint le plus rapide en 4G.

### C. Cas mot de passe (destinataire + clavier mobile)
Etapes : page serrure, comprendre, taper mot de passe, valider, erreur eventuelle.
Les 3 : carte centree, 1 champ, erreur douce. Frictions reelles oubliees partout : aucun ne precise `inputmode`, `autocapitalize=off`, `autocorrect=off` ni bouton afficher le mot de passe, critiques sur mobile. Aucun ne precise le bouton aller du clavier (type submit + `enterkeyhint="go"`). P-lecture-first et P-robuste gardent le gabarit lecture, bien pour la confiance. P-admin-power parle de carte mais pas du lien vers expiration : un lecteur qui se trompe 2 fois doit savoir si c est faute de frappe ou lien mort.

### D. Cas lien expire (pire moment, zero confiance)
Etapes : tap vieux lien, page d erreur, comprendre, ne pas accuser l expediteur.
Les 3 : message neutre sans code, bien. Manques communs : aucun bouton Reessayer inutile ici, mais aucun ne propose Copier le titre ou Contacter l expediteur via part directe. P-robuste a la formulation la plus claire ("Ce lien est invalide ou expire"). P-lecture-first veut bouton Copier le lien en pied meme sur page expiree : absurde, il n y a rien a copier. P-admin-power ne distingue pas visuellement expire et mot de passe requis : meme gabarit = confusion.

## 2. Points de friction par proposition

P-lecture-first : top bar publique surchargee. Sommaire ouvert par defaut repousse la lecture. Bouton Copier en pied sur page d erreur. KaTeX avec CDN SRI sans repli texte explicite cote template. Theme manuel prioritaire sur auto = flash possible si script anti flash rate.
P-admin-power : admin dense qui deborde sur 360px (header + recherche sticky cumules = 30 pourcent d ecran perdu). Bottom sheet custom = risque a11y et temps. Police serif via CDN en premier : si Fonts lent, CLS ou flash sur article. Wrap 46rem incoherent avec 65ch annonce.
P-robuste : systeme d abord avec CDN en progres = meilleur premier paint, mais fallback Georgia seul plus froid, a compenser par interlignage. Confirm natif anxiogene. Pas de compteur de vues ni d aide mot de passe cote admin decrits assez concretement. Le plus honnete sur les pannes, le moins detaille sur le succes de copie.

## 3. Classement motive

1. P-robuste : gagne car il optimise le seul moment qui compte, le premier paint du destinataire sans compte sur reseau faible. La degradation en 3 niveaux est la seule reponse concrete a la friction reseau.
2. P-admin-power : deuxieme, meilleur parcours proprio (segments, validation inline, compteur), mais perd a cause du poids : bottom sheet, header dense, serif CDN prioritaire.
3. P-lecture-first : troisieme, bonne intention lecture mais ajoute des objets (theme, sommaire ouvert, pied copier partout) qui retardent la lecture au lieu de la servir.

## 4. Fusion proposee, friction zero

Garder de P-robuste : base systeme + CDN optionnel, pipeline serveur Pygments + arithmatex generic, repli texte maths, `defer` partout, print et reduced-motion, page expiree sans CTA copier.
Garder de P-admin-power : recherche sticky + compteur + croix, segments duree + details, validation inline avec focus premier fautif, cartes liens + tableau des 800px, toast Annuler 5s. Jeter son bottom sheet, garder confirm inline simple dans la carte (bouton Revoquer devient Confirmer + Annuler, zero dialogue).
Garder de P-lecture-first : colonne 40rem + 65ch, progression 3px, callouts 3 max, code scroll-x + Copier.
Ajouts friction zero : champ password avec afficher, `enterkeyhint="go"`, `autocorrect off`. Toast "Lien copie" systematique + vibration legere si dispo. Sommaire replie par defaut toujours. Top bar publique reduite a logo + badge, theme range en pied. Sur page expiree : message + bouton Partager a nouveau visible seulement si cle admin en session.
Regle d or : destinataire lit en moins de 2 s sur 4G sans JS. Tout le reste est optionnel.
