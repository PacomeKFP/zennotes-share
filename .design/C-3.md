# C-3 : faisabilite technique des 3 propositions

## 1. Socle actuel, points de friction communs
- `app.py` : templates inline + `PAGE_HTML.format(...)`. Tout `{` CSS/JS doit etre double. Gros `BASE_CSS` inline = risque d'erreur `format` silencieux et relecture penible. Aucune proposition ne traite ce point.
- `render.py` : `extra + codehilite + toc + sane_lists` + bleach minimal (`label` absent, pas de `class` sur `li/ul/label`). Passer a pymdownx exige MAJ allowlist sinon bleach mutile tasklist et arithmatex.
- Tests `tests/test_links.py` : fragile sur un point, `"<li>" in html`. Avec `tasklist custom_checkbox True`, `- [ ]` rend `<li class="task-list-item">`, le literal `<li>` disparait. Il faudra assouplir le test en `<li` ou ajouter un cas liste simple.

## 2. P-lecture-first : public star, admin sobre
- Casse : rien de structurel. Pipeline pymdownx + bleach decrit mais oublie `label` dans `ALLOWED_TAGS` (cite seulement `class`). A corriger sinon cases ciselees.
- CDN : serif + Inter via Google Fonts (1 link, swap) = leger et acceptable. KaTeX defer + SRI, versions OK (`>=0.16.21`, couvre CVE-2025-23207). Ordre `$$` puis `$` correct.
- Inline : ajoute progression JS, sommaire `details`, copie code, retour haut, print. Volume JS modere, testable sans framework. Risque principal : theme anti-flash + `format` braces.
- Tests : OK hors ajustement `<li` ci-dessus. `guess_lang False` garde le cas "code inconnu neutre" stable.
- Effort : moyen, environ 3 j (1 j rendu + tests bornes, 2 j gabarits + recette 360/1280/200 %).

## 3. P-admin-power : admin dense, public simple
- Casse : c'est la plus risqueuse. Bottom sheet mobile custom + double rendu cartes/tableau + focus trap + `Esc` = le plus de JS inline, donc le plus de regressions clavier et tactiles. `confirm` natif ferait le meme travail.
- Bleach : la plus precise (liste tags + attrs explicite, refuse MathML/SVG/b64/snippets). Bon point secu, a conserver.
- CDN : meme cout KaTeX + fonts que les autres, mais ajoute Pygments CSS via `HtmlFormatter` a generer une fois. Attention pin `Pygments<2.21` (2.20 casse superfences) et `pymdown-extensions==11.0.2` (ReDoS).
- Tests : meme ajustement `<li` requis. Logique `links` inchangee, donc coeur metier intact.
- Effort : le plus eleve, environ 4 a 5 j (admin seule vaut 2 a 3 j avec sticky CTA, segments, toast Annuler, etats vide/hors ligne).

## 4. P-robuste : sobre avec replis
- Casse : rien. Seule proposition qui definit niveaux 0/1/2 (sans JS, fonts OK, KaTeX OK) et exige texte source lisible si CDN mort. Approche la plus compatible avec `no-store` et pages ephemeres.
- Bleach : correct sur l'esprit mais formulation ambigue ("ajouter label + class sur..."), a rendre explicite comme P-admin-power.
- CDN : systeme par defaut, Google Fonts en progres non bloquant, zero `@import`, `defer` partout. Poids minimal au premier paint, pas de highlight.js en cumul (bon choix, Pygments serveur suffit).
- Tests : idem, un seul ajustement `<li`. Refus explicites (b64, snippets, MathML/SVG, bottom sheet) reduisent la surface de maintenance.
- Effort : le plus faible, environ 2 a 3 j, car `confirm` natif et composants sobres.

## 5. Classement motive
1. P-robuste : risque minimal, replis testes, refus sains, effort faible. Base ideale.
2. P-lecture-first : bon complement public (hero, sommaire, print) une fois la base robuste posee.
3. P-admin-power : bleach precise a piller, mais bottom sheet et densite JS a refuser en v1.

## 6. Fusion la plus sure + replis
- Socle = P-robuste (tokens, niveaux 0/1/2, `confirm` natif, toast simple). Prendre allowlist bleach de P-admin-power (explicite, avec `label` + `input[checked,disabled,type]`).
- Ajouts P-lecture-first limites au public : progression 3 px, sommaire `details` si 3+ h2, copie code, print CSS, theme auto + manuel.
- Securiser l'inline : remplacer `format` par `string.Template` ou marqueurs `__CONTENT__` pour eliminer le piege des accolades, puis decouper `BASE_CSS`, `PUB_HTML`, `ADMIN_HTML` en constantes separees.
- Plan de repli par morceau : pymdownx indisponible = garder `extra+codehilite` ; KaTeX KO = source `$..$` visible en scroll-x ; fonts KO = systeme immediat ; copie JS KO = bouton masque en no-JS ; sommaire sans `toc` = section masquee ; bottom sheet = jamais, `confirm` natif.
- Etape 0 obligatoire : pinner deps, ajouter `label` + classes bleach, assouplir test `<li` en `<li`, ajouter tests bornes (`$$` multiligne, `$` dans code, `$2.50` non rendu, tableau align).
