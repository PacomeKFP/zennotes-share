# C-1 : critique comparative (lecture-first vs admin-power vs robuste)

## P-lecture-first : le public star, admin correct
Forces : seul a detailler le public section par section (progress 3px, sommaire details, print-only URL+date, password et 404 au meme gabarit, bouton retour haut, Copier code). Pipeline rendu le plus teste (bornes maths, code inconnu, tableaux). Mobile concret : 360px, zero scroll-x page, scroll interne + tabindex, 44px, reduced-motion, recette 390/1280/zoom 200.
Faiblesses : admin le plus pauvre (pas de navigateur notes pousse, pas de validation inline detaillee, pas d offline). Serif CDN par defaut sans strategie de repli : si Fonts bloque, FOUT/CLS sur la page qui compte le plus. Refus discutable : zebrage figeable refuse (ok) mais libelle theme refuse au profit d icone seule, moins clair en a11y.
Risques : dependance Fonts sur le premier paint public. Poids KaTeX (~300 Ko defer) accepte mais sans fallback decrit.

## P-admin-power : l admin star, public volontairement simple
Forces : admin de loin le plus utilisable au pouce (recherche sticky + compteur + croix, cartes compactes, segments duree, details options, CTA sticky 48px, cartes liens + tableau 800px+, validation inline + focus premier fautif, offline + Reessayer, toast Annuler 5s). Tokens les plus complets (radius, shadow, hyphens, balance/pretty). Secu explicite (frontmatter strip, wikilinks avant markdown, jamais MathML/SVG, pins + CVE).
Faiblesses : public avoue simple, donc sous la contrainte produit principale (page publique impeccable). Incoherence mesure : wrap 46rem d un cote, 65ch/40rem de l autre, a trancher. Bottom-sheet custom mobile : le composant le plus cher du lot (JS, focus piege, Esc, tests clavier) pour un gain faible sur une action destructive rare.
Risques : complexite. C est la proposition la plus longue a implementer et a recetter. Pygments + KaTeX + Fonts cumules sans regle de degradation : echec CDN = page degradee non specifiee.

## P-robuste : le socle qui ne casse jamais
Forces : seule proposition avec niveaux de degradation N0/N1/N2 (sans JS ni CDN : lecture complete, code colore serveur, maths en source lisible). Systeme d abord, CDN en progres : zero CLS, meilleur cold start Modal scale-to-zero. Confirm natif au lieu de bottom-sheet : moins joli, zero bug. Anti-flash theme dans head, defer partout, pas de @import.
Faiblesses : esthétique la moins differentiante (systeme par defaut = lecture froide si Fonts echoue souvent). Hierarchie couleur faible (--accent = --link). Admin moins specifie que admin-power (validation, compteur, offline resumes trop vite). Formule auto + localStorage decrite mais articulation avec media un peu floue en v1.
Risques : quasi aucun. C est le choix le plus sur en dependances, poids et complexite. Risque inverse : produit juge fade cote public si on s arrete la.

## Risques techniques transverses
Rendu : les trois convergent (superfences + highlight Pygments guess_lang False + arithmatex generic smart_dollar + KaTeX client SRI defer + bleach strict sans script/style/on*). Bon. Points de vigilance : pinner pymdown-extensions==11.0.2 et Pygments<2.21 (2.20 casse superfences), toc avec slugify stable, ordre auto-render $$ puis $ puis \( \) et \[ \], bleach doit garder class sur span/div/pre/code + label pour tasklist.
Poids : KaTeX + Fonts = 90 % du poids public. Defer + display=swap + fallback Georgia/system-ui obligatoires, sinon premier paint fragile sur mobile.
Complexite : bottom-sheet custom (admin-power) = seul vrai piege JS. Tout le reste est HTML/CSS/vanilla a portee.

## Classement
1. P-robuste comme socle : seul a garantir les contraintes scale-to-zero, sans build, lisible sans CDN. 2. P-lecture-first pour le public : le seul au niveau d exigence attendu sur /s/{token}. 3. P-admin-power pour l admin : le meilleur cahier admin, a reprendre en version allegee (sans bottom-sheet).
Ordre motive : sans socle robuste, le beau public casse au premier CDN lent ; sans lecture-first, le produit rate sa vitrine ; l admin-power est un bonus, pas le coeur.

## Proposition de FUSION
Pipeline : prendre le commun strict (config admin-power section 4 + replis robuste + tests bornes lecture-first). Interdire highlight.js en cumul, b64/snippets, MathML/SVG.
Public : prendre lecture-first integral (top bar + hero + sommaire + callouts 3 max + Copier code + retour haut + password/404 gabarit + print) avec degradation robuste (source maths lisible, fallback systeme).
Admin : prendre admin-power sans bottom-sheet : 1 colonne 360px, recherche sticky + compteur, segments duree, details options, CTA sticky, cartes + tableau 800px+, confirm natif + toast Annuler 5s, offline + Reessayer. Refuser le bottom-sheet custom.
Tokens/CSS : tokens lecture-first (bg #fbfaf7, 65ch/40rem, clamp h1) + fallback systeme robuste en premier, serif/Inter en progres. BASE_CSS 7 blocs R1-css, prefixes .pub-/.adm-, BEM, focus 2px offset 2px, reduced-motion, print R1-a11y.
Recette : 360px zero scroll-x, 1280px, zoom 200 %, contrastes AA clair/sombre, CDN coupe (polices + KaTeX), Entree/Esc clavier seul.
